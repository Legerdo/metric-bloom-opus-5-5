# Metric Bloom 검증 기록

검증일: 2026-09-27. 대상은 이 디렉터리의 실제 checkout과 `npm run build`로 생성한 `dist/`입니다. 사람의 전체 플레이 시간 측정과 가속 경제 시뮬레이션을 구분합니다.

## 경제 진행

`scripts/balance.ts`는 렌더러와 분리된 실제 게임 경제 함수를 호출합니다. 새 게임 상태에서 시작해 발행, 구매, 연구, 기여, 배분, 연결망, 시즌 선택과 최종 방송을 진행합니다. 자원 직접 지급 또는 엔딩 플래그 강제 설정은 사용하지 않습니다.

| 전략 | 엔딩 시간 | 주요 돌파 사이 최대 간격 | 구매 없는 최대 구간 | 시즌 전환 후 이전 관심 생산 회복 |
| --- | ---: | ---: | ---: | ---: |
| 적극적 배분·이벤트 활용, 새 계절 | 84.82분 | 10.80분 | 98초 | 48초 |
| 일반 간격의 구매·배분, 새 계절 | 97.02분 | 9.47분 | 146초 | 120초 |
| 느린 구매·균등 제작 유지, 새 계절 | 144.02분 | 16.80분 | 206초 | 170초 |
| 재출발 없이 연속 제작 협약 | 98.35분 | 12.88분 | 98초 | 해당 없음 |

모든 전략에서 첫 자동 생산은 시뮬레이션 6초에 시작합니다. 일반 전략은 최초 발행 31회 이후 반복 클릭 없이 끝까지 진행합니다. 구매 우선순위와 배분을 사용하는 전략 모델이므로, 아무런 선택 없이 처음부터 끝까지 방치해도 동일한 시간에 끝난다는 의미는 아닙니다.

자동 검증 기준은 모든 전략의 180분 이내 엔딩, 일반 전략의 90~150분 완료와 15분 이하 주요 돌파 간격, 30초 이내 첫 자동 생산, 5분 이내 구매 기회 및 시즌 후 이전 생산 회복, 유한한 양수 생산량입니다. 한 가지 고정 구매 순서만 테스트하지 않습니다.

적극적으로 최적화한 전략은 90분보다 빠르게 끝납니다. 느린 균등 제작 전략의 가장 긴 주요 돌파 간격은 16.8분으로, 5~15분의 설계 목표를 소폭 넘습니다. 전체 기록과 각 계획 도달 시점은 `evidence/balance.json`에 남깁니다.

## 실제 브라우저에서 확인한 흐름

1. **정상 속도 시작:** 시작 버튼, 네 번의 발행, 첫 작업대 구매, 실제 자동 생산, 가까운 생산 돌파 목표, 저장과 새로고침 복구. 배포 빌드의 디버그 API 미노출도 확인합니다.
2. **제작과 연결망:** 제작 방향, 배분 합계 100%, 모듈 변경과 저장, 작은 화면의 수평 넘침 및 주요 버튼 가시성.
3. **오프라인 복귀:** 한 시간 경과한 저장을 불러와 최대 30분·50% 효율을 적용하고, 결과 요약 및 새로고침으로 보상이 중복 지급되지 않음을 확인합니다.
4. **최종 방송:** 필요한 제작 배분이 부족하면 기여가 막히고, 올바른 배분과 연결 경로를 맞추면 실제 기여가 진행됩니다.
5. **연속 제작 협약:** 취소 시 상태 보존, 명시적 확정 후 기존 설비와 연결망 유지, 새 계절과의 상호 배타성.
6. **오디오·접근성:** 음악과 효과음 독립 조절, 움직임 줄이기 설정, 새로고침 후 복원.
7. **실제 엔딩:** 마지막 개막 버튼, 전용 결말·통계·크레딧, 완성된 마을 둘러보기, 완료 상태 저장과 복구.
8. **새 계절:** 실제 확인 버튼을 통한 전환 및 영구 배율·보존 상태 확인.
9. **저장 내보내기/가져오기:** 실제 다운로드 및 파일 선택 흐름으로 검증된 저장을 교체합니다.
10. **여러 탭:** 다른 탭의 저장 변경을 감지한 창이 진행을 덮어쓰지 않도록 멈추는지 확인합니다.

중후반 브라우저 테스트는 경제 시뮬레이션에서 정상 규칙으로 도달한 저장을 불러와 해당 화면의 실제 버튼으로 이어서 진행합니다. 브라우저에서 2시간을 실시간으로 기다린 E2E는 아닙니다.

## 시각적 검증

기본 1440×1000, 노트북 1366×768 및 1024×768, 세로 화면 768×1024 및 390×844를 캡처합니다. 노트북에서는 스크롤 전에도 발행과 목표 기여 버튼 전체가 화면 안에 있도록 회귀 테스트로 고정했습니다.

`evidence/early.png`, `mid.png`, `late.png`, `ending.png`, `renewal.png`, `viewport-*.png`에서 초반 한 작업실과 후반 여러 지붕·다리·방송탑·서가·주민으로 확장된 마을을 비교할 수 있습니다. 이번 작업에서 초반·중후반·엔딩 및 1024px 화면을 직접 확인했습니다.

## 이번에 발견해 수정한 문제

* 설비 50개 이후 생산 단계 보상이 끊기는 구간에 75·100·125개 이후의 실제 생산 돌파를 추가하고, 다음 목표 수량을 표시했습니다.
* 리믹스 연구의 실제 합산 배율과 설명이 일치하도록 고쳤습니다.
* 재출발을 하지 않는 경로의 후반 지연을 줄이기 위해 연속 제작 협약을 공통 정의의 4배 생산으로 조정했습니다. 규칙, UI, 확인 창, 테스트가 같은 값을 참조합니다.
* 새 계절/협약 선택이 설계 패널 아래에 묻히지 않도록 해당 단계의 설계 탭 진입 시 선택 영역을 보여주고, 목표 안내에도 선택을 표시했습니다.
* 1024×768에서 목표 기여 버튼의 하단 약 1px가 잘리는 문제를 실제 뷰포트 테스트로 발견하고, 충돌하던 짧은 화면용 상단 여백 규칙을 수정했습니다.

## 검증 범위의 한계

전체 본편을 사람이 90~150분 동안 직접 플레이해 재미와 체감 난도를 평가하지는 않았습니다. 시뮬레이션 결과는 지정한 전략들의 도달성·수치·대기 구간 검증이며 모든 가능한 선택의 소요 시간을 보장하지 않습니다. 실제 Chrome의 데스크톱 실행을 확인했으며 별도 스마트폰 실기기, Safari, Firefox는 검증하지 않았습니다. 오디오 설정 동작은 자동 검증했지만 사람의 청취 평가는 별도입니다.

공개 배포, 원격 업로드, Git 커밋·푸시는 수행하지 않았습니다. 로컬 서버는 사용자 PC의 루프백 주소에만 바인딩합니다.
